# Improved Prompt

## Objective
Analyze and recommend the best strategy for ensuring AI coding agents (Claude Code, Cursor, etc.) have accurate Stripe Apps documentation and context — clearly differentiated from Stripe Payments/Checkout integration docs.

## Background
I'm building a Stripe App for the Stripe App Marketplace. My project already uses Stripe for payments (see CLAUDE.md stack: Next.js 15, Supabase, Stripe). AI agents working on this codebase must distinguish between:

1. **Stripe Apps** — Apps built with the Stripe Apps SDK that run inside the Stripe Dashboard (UI extensions, custom views, third-party integrations via Stripe's app platform)
2. **Stripe Payments** — Payment processing integration (Checkout, Elements, webhooks, subscriptions) which this project already has

Agents currently conflate these two domains, leading to incorrect suggestions and wasted time.

## Analysis Requirements

### 1. Documentation Source Audit
- Identify the canonical Stripe Apps documentation (https://docs.stripe.com/stripe-apps)
- Identify Stripe Apps SDK references, CLI tools (`stripe apps`), and API surfaces
- Map which docs are Stripe Apps vs Stripe Payments to define a clear boundary

### 2. Agent Context Delivery Mechanisms
Evaluate strategies for injecting Stripe Apps context into AI agents:
- **CLAUDE.md / Project Rules** — Inline rules and doc references
- **Local docs mirror** — Fetched/cached Stripe Apps docs in-repo (e.g., `.stripe-apps-docs/`)
- **MCP servers** — Custom or existing MCP server for Stripe Apps docs
- **Agents.md pattern** — Similar to the Next.js agents-md pattern already in CLAUDE.md
- **Curated reference files** — Hand-crafted context files with key concepts, gotchas, and disambiguation rules

### 3. Disambiguation Strategy
- Propose explicit rules/instructions that prevent agents from confusing Stripe Apps with Stripe Payments
- Define keyword triggers (e.g., "app manifest", "ui extension", "stripe apps start" → Stripe Apps context; "checkout session", "payment intent", "webhook" → Stripe Payments context)

### 4. Recommendation
- Rank approaches by: accuracy, maintenance burden, token efficiency, and ease of setup
- Recommend a primary strategy with fallback

## Output
Generate a structured analysis report saved to `.ops/analysis/stripe-apps-agent-context.md` containing:
- Executive summary
- Documentation source mapping
- Strategy comparison matrix
- Recommended approach with implementation steps
- Disambiguation rules for CLAUDE.md

## Constraints
- Must work with Claude Code (primary) and be portable to other AI coding tools
- Must not bloat context window — token-efficient solutions preferred
- Must be maintainable as Stripe Apps SDK evolves
- Do not implement — analysis and recommendations only
