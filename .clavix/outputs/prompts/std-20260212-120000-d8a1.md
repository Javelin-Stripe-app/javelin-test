# Improved Prompt

Objective: Research and document the design boundaries and constraints of building a Stripe App (Dashboard extension) using the Stripe UI Toolkit.

Context:
- This is a Stripe App project using React 17 and the Stripe UI Toolkit
- All UI must live within the Stripe Dashboard extension viewport
- Reference: `.stripe-apps-docs/ui-components.md` and `.stripe-apps-docs/core-concepts.md`

Research Questions (answer each explicitly):

1. **Component Requirements**
   - Are we required to use only Stripe UI Toolkit components?
   - Can we create custom React components that wrap or compose Toolkit components?
   - Can we use raw HTML elements (div, span, input) alongside Toolkit components?

2. **Styling Constraints**
   - Can we use Tailwind CSS, CSS Modules, or inline styles?
   - Can we import custom CSS files?
   - What styling mechanisms does the Stripe UI Toolkit provide (props, theming)?

3. **Layout & Visual Boundaries**
   - What viewport sizes and layouts are available (ContextView, FocusView, etc.)?
   - Can we control spacing, typography, or color beyond what Toolkit provides?
   - Are there fixed headers, footers, or navigation patterns we must follow?

4. **Unsupported Patterns**
   - What common UI patterns are NOT possible in Stripe Apps?
   - What are the known design limitations developers hit?

Output Format:
- Structured report with sections matching each research question
- Include specific references to Stripe documentation for each finding
- Flag any gray areas or undocumented behaviors

Save Location: `.ops/analysis/stripe-app-design-boundaries.md`
