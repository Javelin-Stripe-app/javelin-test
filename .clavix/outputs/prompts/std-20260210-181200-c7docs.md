# Improved Prompt

## Objective
Add a comprehensive "External Documentation" rule to CLAUDE.md that instructs AI agents
to use the Context7 MCP server for looking up current documentation before writing code
that touches any external service or library.

## Context
- CLAUDE.md already has a "Next.js Documentation" section using Context7 (`/vercel/next.js`)
- This rule should expand that pattern to cover ALL key external dependencies in the stack
- The rule belongs in CLAUDE.md so it loads automatically every session

## Services to Cover
Expand the existing Next.js Documentation section into a broader rule covering:
- **Next.js** (`/vercel/next.js`) — already exists, keep it
- **React 19** — component patterns, hooks, Server Components
- **Supabase** — client setup, RLS, auth helpers, database queries
- **Stripe** — checkout, webhooks, billing portal, subscriptions
- **Google OAuth** — OAuth 2.0 flows, token handling, scope configuration
- **Tailwind CSS** — utility classes, configuration, plugins
- **Zod** — schema validation patterns

## Requirements
1. Replace the existing "Next.js Documentation" section in CLAUDE.md with a broader
   "External Documentation" section
2. List each service with its Context7 library ID (resolve IDs first using
   `resolve-library-id`)
3. Include a blanket rule: for ANY external library not listed, agents must use
   Context7's `resolve-library-id` to find docs before writing integration code
4. Keep the rule concise — no more than ~15-20 lines
5. Maintain the existing tone and formatting of CLAUDE.md

## Success Criteria
- The new section replaces the narrower Next.js-only rule
- Every key stack dependency has a resolved Context7 library ID
- Agents are instructed to NEVER rely on training data for external API patterns
- A catch-all rule covers unlisted libraries
